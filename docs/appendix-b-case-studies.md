## B.1 节点压力驱逐故障
<!-- 覆盖：K8s 底座、运行时、SRE 稳定性治理 -->

- **故障现象**：某节点内存/磁盘压力持续升高，kubelet 触发节点压力驱逐，大批 Pod 被驱逐重调度，引发服务短暂抖动；重调度过程中部分 Pod 因资源不足卡 Pending，业务延迟飙升。告警（13 章）触发，值班介入。
- **覆盖章节**：第 4 章（节点/控制面）、第 6 章（运行时/cgroup 资源）、第 7 章（资源配额/调度）、第 13 章（告警/SLO）、第 5 章（机械自愈/重调度）。
- **根因定位**：节点资源长期高水位未治理——(1) 容器未设 limit 或 limit 过大（6.2/7.4），noisy neighbor 吃满节点；(2) 节点资源容量无预警（14.2 容量预估缺位）；(3) PDB 未配，驱逐直接打穿可用副本（5.3）。根因是资源治理与容量管理缺位，非节点本身故障。
- **处置过程**：(1) 止损优先（13.3）——紧急扩容节点（Cluster Autoscaler）+ 限制驱逐影响面；(2) 复盘定位根因（14.4 五问）→ limit 缺失 + 容量无预警 + 无 PDB；(3) 修复：全容器强制 request/limit + LimitRange 兜底（7.4）、节点资源水位告警（12/13 章）、关键服务配 PDB（5.3）。
- **长效治理**：(1) 资源 request/limit + ResourceQuota + LimitRange 全覆盖（7.4）；(2) 节点容量水位常态化观测 + 预警（14.2）；(3) 关键服务 PDB 保证驱逐不打穿（5.3）；(4) 容量预估定期化（14.2）。根因模式反哺 L2 自治（16 章）——资源高水位自动触发扩容。

## B.2 GitOps错误发布故障
<!-- 覆盖：GitOps 交付、灰度治理、全域可观测 -->

- **故障现象**：一次 prod 发布，某服务 values 误改（副本数/资源配置错），全量发布后服务过载。因当时无灰度（全量发布，11.1），错误直达全量用户，错误率飙升、SLO 破（13.2）。可观测（12 章）发现错误率异常，但已是全量影响。
- **覆盖章节**：第 10 章（GitOps）、第 11 章（灰度/回退）、第 12 章（可观测）、第 13 章（SLO/告警/故障流程）。
- **根因定位**：(1) 无灰度——全量发布把风险全暴露（11.1）；(2) 评审缺位——values 误改未经评审直合并（10.4）；(3) 可观测虽在但无前置拦截（灰度本可在小流量阶段捕获）。根因是变更风险治理缺位，非可观测不力。
- **处置过程**：(1) 止损优先（13.3）——`git revert` 误改 commit，ArgoCD 自动同步回退（10.2），分钟级恢复；(2) 复盘（14.4）→ 无灰度 + 无评审；(3) 修复：所有 prod 变更走金丝雀（11.2 Argo Rollouts）、values MR 强制评审（10.4）、灰度配自动熔断回退（11.3）。
- **长效治理**：(1) prod 变更强制金丝雀 + 自动熔断回退（11 章）；(2) values MR 评审 + 分支保护（10.4）；(3) 可观测前置——灰度期对比 canary vs stable 指标（11.5）；(4) 变更全流程标准化（11.4）。根因模式反哺 L2 变更自治（16.4 闭环）。

## B.3 GPU算力资源瓶颈故障
<!-- 覆盖：异构算力调度、资源治理、FinOps 成本优化 -->

- **故障现象**：AI 推理服务负载增长，GPU 资源不足，扩容时新 Pod 申请 GPU 一直 Pending（GPU 配额耗尽/节点不够）；同时部分 GPU 利用率低下（冷热不均），单 Token 成本飙升（17.5）。服务延迟劣化，算力瓶颈与成本浪费并存。
- **覆盖章节**：第 17 章（异构算力/资源管控/FinOps）、第 7 章（调度/配额）、第 14 章（FinOps/容量）、第 16 章（KEDA 弹性）。
- **根因定位**：(1) 算力调度不均——冷热不均（17.2 负载均衡缺位）；(2) GPU 配额/容量无预估（14.2/17.2）；(3) 无闲时复用，GPU 闲时空转（17.5）；(4) 弹性用 HPA（不懂推理信号），扩容滞后（7.5/16.3）。根因是 GPU 资源治理与 FinOps 缺位。
- **处置过程**：(1) 止损——紧急加 GPU 节点 + 调度均衡（17.2）；(2) 复盘（14.4）→ 调度不均 + 容量无预估 + 闲时浪费 + 弹性信号错配；(3) 修复：GPU 负载均衡调度（17.2）、容量预估定期化（14.2/17）、闲时复用（17.5）、弹性换 KEDA 推理信号驱动（16.3）。
- **长效治理**：(1) GPU 负载均衡 + 配额（17.2）；(2) 容量预估定期化（14.2）；(3) 闲时算力复用 + 单 Token 成本度量（17.5）；(4) KEDA 推理信号弹性（16.3）。根因模式反哺 L3 自治（18.7）——算力动态调度自治。

## B.4 KV缓存命中率异常性能故障
<!-- 覆盖：AI 推理性能、容量模型、SLO 稳定性 -->

- **故障现象**：AI 推理服务出现"QPS 稳定但 p99 延迟飙升"悖论（18.4），同时 GPU 利用率高但性能劣化。用户感知明显变慢，但平均指标"看起来正常"。运维用平均延迟 SLO 无法捕获（18.6），靠用户投诉才发现。
- **覆盖章节**：第 18 章（推理性能模型/容量/可观测/SLO/自治）、第 12 章（可观测）、第 13 章（SLO/告警）。
- **根因定位**：用全书独家性能模型（18.3）归因——KV 缓存命中率下降（缓存满频繁驱逐，18.2），导致大量重算，TPOT 升高 → p99 延迟飙升；平均延迟被掩盖（18.6），SLO 用平均失准。根因是缓存治理缺位 + SLO 未分阶段百分位。
- **处置过程**：(1) 止损——扩 KV 缓存容量 + 调驱逐策略（18.2），命中率回升，延迟恢复；(2) 用性能模型（18.3）确认瓶颈在 KV 缓存（TPOT 升 + 命中率降）；(3) 修复：SLO 改 TTFT/TPOT p99（分阶段百分位，18.6）、KV 命中率纳入告警（18.5）、容量规划用模型（18.4）。
- **长效治理**：(1) KV 命中率监控 + 告警 + 容量治理（18.2/18.5）；(2) SLO 分阶段百分位 TTFT/TPOT p99（18.6）；(3) 容量规划基于性能模型（18.4）；(4) L3 自治闭环——命中率降自动扩缓存/调度（18.9）。根因模式反哺 L3 智能自治（18.9 闭环）。

## B.5 Agent长任务重试风暴故障
<!-- 覆盖：AI 负载特性、稳定性治理、智能自治 -->

- **故障现象**：智能 Agent 服务某工具偶发超时，触发热重试（无退避无上限，18.8），重试风暴把下游工具服务打挂，级联故障扩散到整个 Agent 链路，多个服务受影响。Agent 长生命周期 + 状态依赖使故障影响面大、恢复慢。
- **覆盖章节**：第 18 章（Agent 运维差异/智能自治）、第 13 章（故障应急）、第 5 章（容错/自愈）、第 16 章（自治闭环）。
- **根因定位**：(1) Agent 重试无治理——多步调用 × 无退避无上限 = 重试风暴（18.8）；(2) 状态依赖——Agent 会话状态随 Pod 丢，重建放大故障；(3) 无级联防护——下游被打挂无熔断隔离。根因是 Agent 运维差异未治理 + 无级联防护。
- **处置过程**：(1) 止损优先（13.3）——限流 + 回退受影响 Agent 服务，隔离故障域；(2) 复盘（14.4）→ 重试无治理 + 状态未外置 + 无熔断；(3) 修复：Agent 重试退避 + 上限（18.8）、会话状态外置（Pod 无状态化，18.8）、下游熔断隔离（8 章/容错）。
- **长效治理**：(1) Agent 重试退避 + 上限（18.8）；(2) 会话状态外置（18.8）；(3) 熔断隔离防级联；(4) L3 自治——重试风暴自愈（限流/熔断自动触发，18.7/18.9）。根因模式反哺 L3 智能自治（18.9 闭环）。

## B.6 企业极简生产架构全链路落地复盘
<!-- 串联全书完整运维控制闭环 -->

- **故障现象 / 复盘主题**：一个企业从第一代被动运维，完整演进到 AI 原生智能自治的全链路复盘——不是单一故障，而是全书核心业务闭环链路（不可变基础设施→…→AI 智能自治）在一家企业的落地实证。
- **覆盖章节**：全书六篇 + 三层自治模型（第 5/16/18 章）。
- **根因定位**（演进驱动）：第一代运维（人工救火）无法承载规模与 AI 负载复杂度，倒逼体系演进。每一代的瓶颈驱动下一代：L1 自愈不够 → 建 L2 业务自治；L2 处置不够 → 建 L3 智能自治。根因（演进动力）是"复杂度增长必须用控制权转移对冲"（1.1）。
- **处置过程**（演进路径）：
  1. **不可变基础设施 + 容器供应链**（第 2 章）：消灭配置漂移，制品可信。
  2. **K8s 底座 + 机械自治**（第 4–8、5 章）：统一运行底座，L1 调谐闭环自愈。
  3. **声明式交付 + GitOps + 灰度**（第 9–11 章）：变更可控、可灰度、可回退。
  4. **全域可观测 + SRE 稳定性**（第 12–14 章）：三支柱协同，SLO 驱动，成本可控。
  5. **平台工程 + 运维自治**（第 15–16 章）：能力平台固化，L2 SLO 驱动自治闭环。
  6. **AI 异构算力 + 推理性能 + 智能自治**（第 17–18 章）：AI 负载专属治理，L3 智能自治闭环。
- **长效治理**（闭环收束）：三层自治递进成型——L1 机械自治（第 5 章）维持基础设施稳态、L2 运维自治（第 16 章）治理业务稳定性、L3 智能自治（第 18 章）优化 AI 复杂动态。全书精神内核落地：**现代运维体系从人工操作，演进为声明式、可观测、可治理、可自治的生产控制系统**。核心业务闭环链路（不可变基础设施→K8s 底座→声明式→GitOps→灰度→OTel 可观测→SRE 治理→平台封装→运维自治→AI 算力→推理性能→KV 缓存→AI 智能自治）在一家企业完整跑通，证明三层递进自治模型是可落地的工程体系，而非理论。
